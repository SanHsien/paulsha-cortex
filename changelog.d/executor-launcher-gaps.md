  2. **copilot executor 無認證巷道**——契約已備，token 佈署留 operator：(a) auth preflight probe 早在 #369（`coordinator/executor_auth.check_executor_auth`）就已支援 copilot 且有完整測試覆蓋，透過 `provider:executor` 動態 sentinel 機制可直接複用；未接上 `cards.yaml` 是既有、刻意的決定（`manager.py` 既有註解：需先確認 CI／各執行環境對 copilot CLI 的可得性，避免 dispatch 熱路徑意外 spawn 子行程），本次不強行打開這個開關——那是跨環境影響面的決策，留給 operator 依實際部署環境判斷。(b) 新增 `launcher._copilot_credential_env()` 並接進 `SubprocessLauncher.launch()`：copilot job env 缺 `COPILOT_GITHUB_TOKEN` 但已有 `GH_TOKEN`／`GITHUB_TOKEN`（三者皆是 copilot CLI 認得、`porcelain/bootstrap.py` 既有 login_fix 訊息記載的候選名稱）時，正規化補上 `COPILOT_GITHUB_TOKEN`（copilot CLI 讀取優先序最高）；`COPILOT_GITHUB_TOKEN` 已存在則不覆寫，三者皆缺則不動 env（fail-soft）。刻意只讀「已注入這個 process 的 env」（daemon 自身 systemd EnvironmentFile／`~/.agents/core/runtime/<instance>.env`，與 `PSC_MANAGER_EXECUTOR` 同一份既有可設定來源機制），不觸碰 gh CLI 的 OS keyring——headless daemon 本就讀不到桌面 keyring，實際把 token 放進佈署環境仍是 operator 的工作。
  3. **claude builder sandbox 擋 git commit → candidate-worktree-dirty**——純 code 修復，root cause 為 launcher 缺口而非 harness/persona 契約矛盾：`build_copilot_argv`／`build_codex_argv` 的 `commit_required` 分支原本就會把 linked worktree 的外部 git 目錄（`.git/worktrees/<name>`、`objects`、`refs`、`logs`——linked worktree 的 `.git` 只是個指向 repo 外部的檔案，真正的 index/objects/refs 都在這些外部路徑）透過 `--add-dir` 放行，唯獨 `build_claude_argv` 從未實作這個參數，`SubprocessLauncher.launch()` 也只把 `commit_required` 傳給 codex/copilot——claude builder 走 `as_commit_required()`（builder persona 既有轉換，三個 executor 理應一視同仁）時因此對 claude 是 no-op，sandbox 因此擋下 `git add`/`git commit`（headless 無人可 approve）。修復：`build_claude_argv` 補上 `commit_required` 參數與同一份 `_linked_worktree_git_write_dirs()` 放行邏輯；`SubprocessLauncher.launch()` 把 claude 併入 `commit_required` 傳遞集合。不需要 persona 契約層加 escape clause——這不是「harness 權限層 vs persona 契約矛盾」，是既有放行機制單純漏接 claude 這一支。
  4. **`slice-action retry-review` 無法補 reviewer identity**——純 CLI 表層缺口：`manager.apply_slice_action`（manager.py:1303-1304）與 `manager_daemon.py` 的 slice-action request 處理（:482-483、:734-735）早已接受並轉發 `review_executor`/`review_model`，`--review-executor`/`--review-model` 在 `complete`/`tick` 也早已存在；缺口純粹是 `coordinator/cli.py` 的 `p_slice_action` 與 `porcelain/recover.py` 的 `slice` 子命令從未把這兩個旗標暴露出來，导致 request args 永遠不帶，`retry-review` 落 `needs_human(reviewer-identity-missing)` 時 CLI 端無路可補。修復：`cortex slice-action <id> retry-review --actor <a> --review-executor <e> --review-model <m>` 與 `cortex recover slice <id> retry-review --actor <a> --review-executor <e> --review-model <m>` 均已可用，未帶時 request args 維持原形狀（不夾帶 `None`，不影響既有 daemon 測試的精確字典比對）。
