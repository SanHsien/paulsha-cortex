### Fixed
- **Issue #371／#375：installer 的 `preserve_existing` 鎖死 managed path 錯誤值，且 manager.lock 未 instance-scoped**：`_write_managed_env` 過去把 `PSC_PROJECT_CONFIG_ROOT` 與 `PSC_RUN_ROOT`／`PSC_MONITOR_STATE_ROOT` 一視同仁放進 `preserve_existing`——但前者純粹是 `PSC_AGENTS_ROOT` 推導值，一旦既有值錯（實測 hippo instance：`PSC_AGENTS_ROOT` 已正確隔離到 instance 專屬路徑，唯獨 `PSC_PROJECT_CONFIG_ROOT` 仍卡在舊的共用預設），`cortex install service` 重裝也永遠修不好，導致多個 instance 實際共用同一份 project config、掃同一組 repo，打爆共用 GitHub 配額（issue #371）。另一方面 `manager.lock` 的路徑完全沒有 instance 成分：shell wrapper（`service-manager.sh`）硬寫 `${PSC_CONTROL_ROOT:-$HOME/.agents/control}/manager.lock`，Python daemon 則走 `control/constants.py` → `config/runtime.py` 的完整 `PSC_AGENTS_ROOT` 解析鏈，兩條規則各自為政；agents_root 相同時兩個 instance 搶同一把鎖（第二個 instance 靜默 adopt 對方 pid、work item 永遠不會被處理），agents_root 不同時兩端又會分歧（issue #375）。兩票都動到 `installer.py` 的 `managed_env`／`preserve_existing`，合併修復：（1）`PSC_PROJECT_CONFIG_ROOT` 移出 `preserve_existing`，每次 install 一律以目前 `PSC_AGENTS_ROOT`／instance 重新推導覆寫；（2）新增 `PSC_CONTROL_ROOT` 進 `managed_env`，預設 `<agents_root>/control/<instance>`（比照 `PSC_RUN_ROOT` 的 `run/<instance>`），且明確**不**放進 `preserve_existing`（否則會複製同一種鎖死 bug）；（3）新增 `cortex control lock-path` CLI 契約，`service-manager.sh` 的 `manager_lock_path()` 改為委派給它（並快取結果避免輪詢迴圈重複 spawn python），與 daemon 同源，消除 shell／Python 兩套硬寫解析規則的分歧；（4）`cortex doctor` 新增 `managed-path-drift` probe，獨立於 install 之外偵測既有安裝的 `PSC_PROJECT_CONFIG_ROOT`／`PSC_CONTROL_ROOT` 是否已跟目前推導值分岔（鍵缺席視為尚未升級的過渡態，僅 warn；鍵存在但值錯才 fail）。`PSC_MANAGER_SPECS_DIR`／`PSC_COORDINATOR_ROOT`／`PSC_SPECS_ROOT` 評估後仍留在 operator 域（牽動面遠大於本次範圍），以 pin 測試與程式註解記錄決策，留待後續 follow-up。新增 19 個回歸測試（installer managed-env 5 個、`cortex control lock-path` CLI 5 個、shell `manager_lock_path` 3 個、doctor drift probe 6 個），修正前皆已確認 RED（`test_install_preserves_existing_operator_env_lines` 等直接重現 #371 的 hippo 場景）。
