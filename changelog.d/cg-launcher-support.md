- **Issue #442（第一部分）：新增 `cg`（copilot API／glm-5.2 via llm-share）launcher 支援**：#396 item 1 當時因 CLI 介面未經證實而刻意 out-of-scope；operator 已提供並 smoke 驗證介面契約（`cg --model {MODEL} --effort {low|medium|high|xhigh} --headless --stdin`：prompt 經 stdin、乾淨 response 於 stdout、summary banner 於 stderr、exit 0 成功），現正式支援。新增 `launcher.build_cg_argv`（回 `["cg", "--model", ..., "--effort", ..., "--headless", "--stdin"]`，model 預設 `glm-5.2`、effort 合法值 `low`/`medium`/`high`/`xhigh` 預設 `medium`）並登記進 `_ARGV_BUILDERS`（`--executor`/`--review-executor` choices 自動同步出現 `cg`）。cg wrapper 自帶 `--available-tools=__none__`＋`--disable-builtin-mcps`＋throwaway HOME，是 zero-tool executor：不能跑任何 tool、寫檔或 commit，因此只服務 read-only 的 planner／reviewer persona，絕不可當 builder——`build_cg_argv` 與 `SubprocessLauncher.__init__` 對 `commit_required`／`allow_unsafe`／既非 `read_only` 也非 `review_only` 的「builder 語境」一律在建構期／build 期 raise（比照 `build_agy_argv` 對 `allow_unsafe` 的拒絕模式）。新增 stdin plumbing：既有 copilot/claude/codex/agy 皆把 prompt 當 argv 一個元素，cg 改在 `SubprocessLauncher.launch()` 產生的 wrapper script 用 `printf %s <prompt> | <inner argv> 2>/dev/null` 把 prompt 經標準輸入餵入，並顯式讓 cg 自身的 stderr（summary banner）與 log 的乾淨 stdout 分離，不混入 JSONL terminal evidence；`stdin_prompt=None`（其餘 executor 的預設路徑）與改動前逐字相同，零影響。改寫 #396 釘住的 `test_cg_executor_is_deliberately_unsupported`（cg 現已支援，改驗 `_ARGV_BUILDERS` 含 cg、builder 語境拒絕、read-only/review-only 皆可正常建構），同步修正 `test_coordinator_cli_flags.py` 一個巧合依賴「cg 未知」的既有測試改用真正未知的 executor 字面值。`paulsha_cortex/deploy/installer.py` 的 `_SUPPORTED_EXECUTORS`（`PSC_MANAGER_EXECUTOR` 專用，僅收 commit-capable 的 primary builder executor）刻意不加 cg：與既有排除在外的 `agy` 同理，cg 結構上永遠無法成為 manager 的主 builder。不改動 `model-identities.yaml`（operator 部署配置，非 repo code）。新增 13 個回歸測試（另移除 1 個因語意反轉而失效的舊測試 `test_cg_executor_is_deliberately_unsupported`，改寫進新測試組），淨增 12；實作前已確認 RED（`ImportError: cannot import name 'build_cg_argv'`）。全套 pytest：2374 passed、32 subtests passed（基線 2362/32，淨增 12；另有 2 個與本票無關的既有環境性失敗，見既有 `/tmp/.git` 汙染說明）。
