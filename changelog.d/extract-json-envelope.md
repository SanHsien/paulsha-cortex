### Fixed
- **Issue #401：`_extract_json` 在 result 非 JSON 時把 CLI envelope 當模型輸出餵進驗證，且 planning prompt 未強制純 JSON**：`planning_runtime._extract_json` 過去對 candidate 解析出的 dict 嘗試 `json.loads` 其 `result`/`content`/`message`/`text` 巢狀字串欄位，一旦失敗就 fall through 直接 `return value`——把整個 CLI 成功 envelope（claude CLI 含 `api_error_status` 等 20+ 鍵）當成模型輸出本體回傳，讓下游 `validate_question_pack` 報出 `unexpected key: api_error_status` 這種完全誤導的診斷（實測 sonnet 對 questioner prompt 回散文推理、內容正確但格式不從，即觸發此路徑）。修法：抽出共用 helper `_find_json_object`（先去除整段 code fence、再嘗試整串 `json.loads`，`allow_partial=True` 時再嘗試平衡大括號掃描——用簡單狀態機忽略字串字面值內的跳脫括號，抓出第一個平衡區塊）；頂層候選字串（CLI 原始 stdout／`--output-file` 內容）維持既有嚴格「整串才算」語意（不啟用平衡掃描），只有 envelope 判定成立（dict 含 `result`/`content`/`message`/`text` 任一鍵）後，才對其巢狀字串欄位用 `allow_partial=True` 從散文中抽取內嵌 JSON；全部抽取失敗時 `raise ValueError`（訊息帶散文片段前 160 字），絕不再 fall through 回傳 envelope dict 本體。另在 `build_production_planning_runtime` 的 questioner／integrator／secondary planner 三處 prompt 統一附加輸出契約字句（`Output contract: reply with exactly one JSON object and nothing else — no prose, no explanation, no code fences. Your reply MUST start with '{'.`），降低模型不遵守純 JSON 格式的機率。新增 5 個回歸測試：envelope + result 散文含內嵌 JSON → 抽出內嵌物；envelope + result 純散文 → `ValueError`（訊息含散文片段、不含 `api_error_status`）；envelope + result 純 JSON 字串／頂層無 envelope 鍵兩種既有行為不變；questioner／integrator（及既有 secondary 測試補充斷言）的 prompt 含輸出契約字句。修正前以 `git stash` 隔離只復原 `planning_runtime.py` 驗證，4 項新行為測試皆確認 FAIL（另 2 項「行為不變」守衛測試修正前後皆通過）。
