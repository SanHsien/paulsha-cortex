### Fixed
- **Issue #399：planning 完整性檢查把 gitignored 的 `runtime/` daemon 狀態目錄雜湊進去，handoff churn 誤判為 planner 汙染**：`.gitignore:8` 明列 `/runtime/` 為本機部署常見拓撲（manager daemon 以 repo 為 `WorkingDirectory` 常駐）下的狀態殘留，`runtime/handoff/wf-*.json` 被 daemon 每個 periodic tick 整份重寫（issue #373 的迴圈使其每 ~55 秒必然發生一次），內容含時間戳必變。`planning_runtime._tree_snapshot`（PR #398 後已排除 `__pycache__`／`*.pyc`）仍雜湊 `runtime/`，被 `_invoke_json` 的 operator 快照前後比對誤判成「planner 修改了 operator worktree」而 fail-closed 到整段 `raise ValueError` + rollback；`_copy_planning_sandbox` 的 `copytree` 同樣照抄複製這棵目錄。修法：`_tree_snapshot` 的目錄走訪新增規則，只跳過**快照 root 直下**的 `runtime/`（以 relative path 判斷，非只比對 dir name），避免誤跳深層同名目錄（例如 `pkg/runtime/`）；gitignored 內容不受版控，verification gate 讀 git diff 判斷候選檔案，跳過雜湊的盲點可控。`_copy_planning_sandbox` 改用自訂 `ignore` callable（取代 `shutil.ignore_patterns`，因其按名稱全樹匹配、無法區分深淺層），只在走訪到 worktree 根目錄時才把 `runtime` 加進忽略清單，與 `_tree_snapshot` 語意保持一致。新增回歸測試釘住雙向行為：root 層級 `runtime/handoff/*.json` 的新增／改寫不得觸發 mismatch，且 `_invoke_json` 整合層級也不得 raise；深層同名目錄 `pkg/runtime/` 的變動仍必須觸發 mismatch（防過度排除）；`_copy_planning_sandbox` 排除 root 層級 `runtime/` 但保留深層同名目錄。修正前三項新測試皆已確認 FAIL。
