### Fixed
- **Issue #439：monitor server.py 的 `os.umask(0o177)` dance 冗餘且為 process-global 併發 footgun（#425 追查副產物）**：`paulsha_cortex/monitor/server.py` 的 `MonitorServer.serve_forever()` 在 Unix socket `bind()` 前後翻 `os.umask(0o177)` 再還原，之後緊接 `os.chmod(str(self._socket_path), 0o600)` 明確設定 socket 權限——umask 的效果完全被 chmod 覆蓋，兩者做同一件事，且 `os.umask()` 是 **process-global 非 thread-local**：monitor server 在背景執行緒跑，umask 被翻到 `0o177` 的窗口內，**任何其他執行緒**同時進行的 `mkdir(parents=True)` 若在該窗口內建立新的祖先目錄，該目錄會繼承 `0o600`（無 execute 位），導致該目錄下後續的 mkdir/stat 拋出 `PermissionError`——這正是 #425（stage9 3.13 CI flaky）的實際機制（#425 當時只在測試側加了 `_mkdir_resilient` 重試緩解症狀，未從源頭消除）。修法：移除 `os.umask(0o177)`／還原的 dance，僅保留其後的 `os.chmod(str(self._socket_path), 0o600)`——socket 權限語意不變（chmod 明確設定最終權限），同時整類 process-global umask race 被消除。`serve_forever` 中在 umask 窗口之外的既有 `self._socket_path.parent.mkdir(parents=True, exist_ok=True)`（bind 之前、`_SOCKET_PATH_LOCK` 之外）本就不受此次變更影響。新增 2 個回歸測試（`tests/test_stage9_project_monitor_service.py::Stage9ServerTests`）：`test_serve_forever_does_not_touch_process_umask`——monkeypatch `paulsha_cortex.monitor.server.os.umask` 為拋例外，斷言 `serve_forever()` 執行路徑不再呼叫 `os.umask`；`test_concurrent_mkdir_keeps_execute_bit_during_serve_forever_bind`——因真實 race window 只有 `bind()` 這一個 syscall 的時間（微秒級、無法穩定重現時序），改以 monkeypatch `socket.socket.bind`（僅測試範圍，不動 production code）插入短暫 sleep 人為放大該窗口，確保 server 執行緒確實停在 `bind()` 內部時，main 執行緒同時對另一路徑做 `mkdir(parents=True)`，斷言新目錄保有 execute 位（未被殘留 umask 污染）。兩測試在修復前皆已確認 RED：前者以 `AssertionError` 從 `os.umask` 呼叫點直接冒出；後者實際重現 `PermissionError: [Errno 13] Permission denied`（與 #425 CI traceback 相符的症狀），修復後兩者皆 GREEN。既有 `test_server_socket_has_0600_permission` 未變動即持續通過，確認 socket 檔權限語意未回退。全套 pytest：2356 passed、32 subtests passed（另有 2 個與本票無關的既有環境性失敗——本機 `/tmp/.git` 污染導致 `test_fix_dispatch_spec_path.py` 的 `_infer_repo_root` 相關 2 個測試紅，非本次變更引入）。
