### Fixed
- **Issue #369：dispatch 前未驗證 executor 登入態，且 provider capability 探測路徑在生產環境為死碼**：`runtime_preflight.py`（#262 設計）的 provider capability 探測（快照＋TTL＋有界 probe 三層）在生產環境從未真正接線——唯一呼叫點 `manager._runtime_preflight_gate` 呼叫 `evaluate_dispatch_gate` 時從未傳入 `snapshot_lookup`／`provider_prober`（兩者預設 `None`），`_resolve_provider_freshness` 在 `snapshot_lookup is None` 時直接判 `STALE_SNAPSHOT`，而 `STALE_SNAPSHOT` 不在 `_BLOCKING_OUTCOMES`（只有 `CAPABILITY_MISSING`／`PROVIDER_UNAVAILABLE` 會擋）——任何 `provider:` 宣告因此永遠放行，整條路徑是死碼；疊加 `cards.yaml` 三處既有宣告皆只有 `module:pytest`、無任何 `provider:` 宣告，即使接線也沒有輸入可觸發。複驗同時發現 `porcelain/bootstrap.py` 的 copilot 登入態判定對輸出做字串匹配（`"login"`／`"authenticate"`／`"device code"`），GitHub 的限流訊息常常同時帶有這些字樣（例如「請重新授權以取得更高額度」），導致限流被誤判成「尚未登入」並錯誤建議 `copilot login`。
  - **接線 provider 探測**（`paulsha_cortex/coordinator/manager.py:5940` `_runtime_preflight_gate`）：新增 `_monitor_provider_snapshot_lookup`／`_combined_provider_snapshot_lookup`／`_combined_provider_prober`（`manager.py:5851-5937`），把 `evaluate_dispatch_gate` 接上兩個真正的資料源——GitHub 走既有 monitor durable snapshot（`monitor.work_snapshot.WorkSnapshotStore`，唯讀，無快照時安全回退 `STALE_SNAPSHOT`，不變更既有保守行為）；executor 走 dispatch-time 的登入態探測（見下）。`_runtime_preflight_gate` 新增可選 `snapshot_store` 參數（預設 `None` 時延後建立真正的 `WorkSnapshotStore()`），供測試注入 tmp_path-scoped store，不觸碰真實安裝路徑。
  - **`provider:executor` 動態 sentinel**（`paulsha_cortex/coordinator/runtime_preflight.py`）：新增 `PROVIDER_EXECUTOR_SENTINEL`，卡片宣告 `provider:executor`（而非寫死的 executor 名稱）時，`run_runtime_preflight` 逐一嘗試 identity candidate 時把它解析成該 candidate 實際使用的 `identity.executor`——builder／manager persona 的 identity 本就會在 claude／codex 之間輪替（`manager._identity_candidates_for_persona`），寫死單一 executor 名稱在換候選時會驗錯 executor。
  - **executor 登入態探測**：新增 `paulsha_cortex/coordinator/executor_auth.py`，`classify_cli_output` 把「CLI returncode ＋合併輸出」分類成 `ok`／`rate_limited`／`logged_out`／`unknown`，**rate limit 判定永遠先於 login 判定**（#369 真正修的缺口）；`check_executor_auth` 對 claude／codex／copilot 做一次有界探測，回傳 `ProviderFreshness`。`manager.py` 以 `_EXECUTOR_AUTH_CACHE`（process-level dict，靠 `ProviderFreshness.is_fresh()` 既有 TTL 語意做跨 dispatch 快取，TTL 沿用 `DEFAULT_PROVIDER_TTL_SECONDS`=900s）避免每次 dispatch 都重新 spawn CLI 子行程。**風險界定**：`cards.yaml` 尚未有卡片宣告 `provider:executor`——sentinel 機制與探測已完整測試覆蓋並可用，但正式接上前須先確認各執行環境（CI／不同 operator 機器）對 claude／codex／copilot CLI 的可得性，避免 dispatch 熱路徑意外 spawn 子行程；留待下一步啟用。
  - **cards 宣告 provider requirement**（`paulsha_cortex/deck/data/cards.yaml`）：`openspec-archive`／`policy-commit` 兩張 ship-phase 卡新增 `runtime_capabilities: ["provider:github:hamanpaul/paulsha-cortex"]`——這兩張卡負責把變更真正落地到 GitHub（archive 對帳、conventional commit 後續 push/PR），provider snapshot degraded 時應擋在 dispatch 前，避免耗費一整個 session 後才因連線問題失敗。僅這兩張卡宣告，其餘 13 張卡不受影響（謹守 R1「未宣告的 card 完全走原路徑」的 no-op 契約）。
  - **修 bootstrap copilot 誤判**（`paulsha_cortex/porcelain/bootstrap.py:_executor_status`）：copilot 分支改用 `executor_auth.classify_cli_output` 共用分類，rate-limit 訊號優先於 login 訊號；限流時回報「copilot 觸發流量限制，暫時無法確認登入態」並建議稍後重試，不再誤導成需要重新登入。
  - 新增 29 個回歸測試（`tests/test_dispatch_runtime_preflight.py` +5、新檔 `tests/test_executor_auth.py` 24 個、`tests/test_porcelain_bootstrap.py` +1），涵蓋：degraded snapshot 在 TTL 內必須硬擋 dispatch（`PROVIDER_UNAVAILABLE`）；無 snapshot 時安全回退（`STALE_SNAPSHOT`，non-blocking）；`provider:executor` sentinel 對不同 candidate 各自解析出正確 executor；出貨 deck 的 `openspec-archive`／`policy-commit` 真的宣告了 `provider:github:...`；`classify_cli_output` 的 rate-limit／login/unknown 分類矩陣（含「限流訊息同時含 login 字樣」的核心案例）；copilot 限流輸出不再誤判為 logged-out。修正前以 `git stash` 隔離個別檔案已確認 RED：manager wiring 測試因 `_runtime_preflight_gate()` 缺 `snapshot_store` 參數直接 `TypeError`；bootstrap 測試斷言失敗於實際輸出仍是「copilot 已安裝，但尚未登入」。全套 pytest：2175 passed、32 subtests passed（基線 2146/32，淨增 29）。
