### Fixed
- **Issue #414：plan 卡 deterministic pass 不驗證宣告 outputs，導致下一棒 build 的 declared input 必缺**：`assess_planning_completeness` 只看 kind 覆蓋率——workstream todo（kind=plan、accepted）就足以讓 planning 判定 complete，`manager._dispatch_workflow_card` 於是把 plan 卡（如 `writing-plans-light`）deterministic pass（`executor=cortex-manager model=deterministic`），卻從未檢查卡片自己宣告的 `produces` glob（如 `docs/superpowers/plans/*<task-slug>*.md`）是否真的命中檔案；todo 的 ref 通常不落在該 pattern 內。下一棒 build 卡宣告同一 pattern 為 declared input，`_workflow_input_snapshot` 找不到檔案便 `raise ValueError("workflow declared input missing: ...")`，整個 run 卡死在 needs_human、零 job（生產實測 run workflow-e18785acc54e5ad87836）。修法：deterministic pass 這張 plan 卡之前，新增 `_plan_card_declared_outputs_present`，用與 build 端 `_workflow_input_snapshot` 對稱的 `_safe_input_matches` glob 語意驗證卡片宣告的 outputs 是否已存在；缺席時交給新增的 `_materialize_plan_card_output`（最小可行替代——plan 卡在 `planning_complete` 為真時本就沒有「回落正常派工」的路徑，只有 deterministic pass 一條路）把已 accepted 的 kind=plan 內容原樣 materialize 到卡片宣告的（唯一）output pattern 之 canonical 路徑（`docs/superpowers/plans/<task-slug>.md`），透過既有 `_PlanningPublicationTransaction.publish` 做 CAS-safe atomic 寫入，並把新路徑併入 `run.planning_authority`（build worktree 是獨立 git worktree，declared input 缺席時要靠 authority 記錄從 workspace_root seed 進去）；registry 提交失敗時以 transaction 的 in-memory rollback 復原檔案，不留孤兒。不可 materialize（宣告了非單一 output pattern、或找不到已 accepted 的 kind=plan 內容）時 fail-closed：不跳過、不動 registry，交由下一輪 dispatch 重新判定。新增 3 個回歸測試（`tests/test_plan_pass_verify_outputs_414.py`）：todo 錨定、outputs 缺席時觸發 materialize 而非直接放行；materialize 後端對端呼叫 `_workflow_input_snapshot` 重現並驗證修復生產事故的確切 `ValueError`（修正前已確認 FAIL，錯誤訊息與生產事故逐字相符）；outputs 已存在時既有正路完全不受影響（不觸發 materialize、`planning_authority` 不多一筆）。另同步調整 `tests/test_workflow_production_wiring.py` 兩個既有測試的 plan fixture ref，使其落在卡片宣告的 canonical outputs glob 內（原本用 `docs/plan.md` 佔位，本身就不符合宣告的 `produces` pattern，恰巧命中本次要修的缺口形狀）。
