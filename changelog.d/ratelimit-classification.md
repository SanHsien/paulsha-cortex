### Fixed
- **Issue #370：`cortex work resume` 撞 GitHub rate limit 無法優雅退避，doctor 的 gh-auth probe 把 rate limit 誤報為憑證失效**：全 repo 過去對 Retry-After／X-RateLimit／secondary rate limit 零處理（`grep` 零命中）。`GitHubWorkProvider.scan()`（`paulsha_cortex/monitor/providers.py:689` 起，錯誤分類於 `:709` 起）把 auth 字樣判定排在 rate limit 之前——GitHub 真實的 secondary/abuse-detection rate limit 訊息常提及「OAuth」或「re-authenticating」，先判 auth 會把可重試的限流誤歸為死憑證。`claim.py::_authority_from_canonical_row`（判準 `github.get("status") != "ok"`）對「provider 因 rate limit degraded」與「provider 真的損毀（malformed／missing／stale timestamp）」共用同一個 `REASON_PROVIDER_INVALID_CANONICAL` reason code，upstream（resume、Manager log）無法不重新解析訊息文字就分辨兩者。`doctor.py` 的 `gh-auth` probe 只看 `gh auth status` exit code（非零一律回 "authentication failed"），rate limit 下的非零 exit code 被誤報成憑證失效，實測差點誤導排障方向去重新授權一個完全正常的 token。resume 撞限流後例外一路冒到 `manager_daemon.py` 的通用 `except Exception`，無條件覆寫 `facets=("needs_human",)`；人工 `cortex work resume` 一律傳 `operator_resume=True`，清掉 `needs_human` 後立即重跑，若限流仍在窗口內立刻再次撞同一道牆，形成「清狀態→立刻重試→立刻再卡」的迴圈，只能人工反覆嘗試直到視窗自然過去。
  - **新增共用分類器**：`paulsha_cortex/github_rate_limit.py`（新檔，`is_rate_limit_signal` / `is_auth_signal`）——rate limit 訊號（`rate limit`／`secondary rate limit`／`abuse detection`／`x-ratelimit`／`retry-after`／`403`／`429`）永遠先於 auth 訊號（`401`／`bad credentials`／`authenticat`／`oauth`）判定，三個消費端（`monitor/providers.py`、`coordinator/claim.py`、`doctor.py`）共用同一套詞彙，避免各自分岔。
  - **分類順序修正**：`GitHubWorkProvider.scan()`（`providers.py:709-719`）改用共用分類器，rate limit 先判，含 authenticate/OAuth 字樣的限流訊息不再誤判為 `"github authentication failed"`。
  - **canonical authority 專屬 reason code**：`claim.py` 新增 `REASON_PROVIDER_RATE_LIMITED_CANONICAL = "provider-authority-rate-limited-canonical"`（`claim.py:39`）；`_authority_from_canonical_row`（`claim.py:428-548`，rate-limit 分支於 `:516-535`）在 `status != "ok"` 且 provider 的 `diagnostics` 含 rate limit 訊號時 raise 這個新 reason code（`field="status"`），與其他 authority-invalid 情境（malformed／missing／真憑證失效）區分；仍是 `AuthorityValidationError`／`ValueError` 子類，既有 broad `except ValueError` call site（如 `mapped_issue_titles`）行為不變。
  - **doctor gh-auth 區分限流與憑證失效**：新增 `_gh_auth_probe`（`doctor.py:86-113`），直接讀 `gh auth status` 的 stdout/stderr（原本的 `_process` 只回傳 stdout，另建函式避免動到其餘 7 處 `_process` 呼叫點），命中 rate limit 訊號回 `status="warn"`（不誤報 authentication failed，附 reset 提示，不影響 `DoctorReport.ok`），否則維持原本的 `"fail" / "authentication failed"`；不把原始 command 輸出寫進 probe detail（沿用既有機密-safe 慣例，`test_doctor_does_not_echo_credentials_from_failed_command` 驗證）。
  - **durable backoff（可複用/擴展既有機制）**：`manager_daemon.py` 的 `_tick_backoff_seconds`（issue #249，指數退避＋封頂）抽成純函式搬到新檔 `paulsha_cortex/coordinator/backoff.py::tick_backoff_seconds`（`manager_daemon.py` 以同名 re-export `_tick_backoff_seconds` 保持相容，`TICK_BACKOFF_MAX_EXPONENT`／`TICK_BACKOFF_MULTIPLIER_BASE` 亦同步 re-export），避免新模組直接 import `manager_daemon` 造成循環 import（`manager_daemon` 已 import `manager`，`manager.resume_workflow_run` 又需要新模組）。新增 `paulsha_cortex/coordinator/provider_backoff.py`：`record_backoff` / `active_backoff` / `clear_backoff` 把「(repo) provider 的下次可重試時間」以 JSON 落盤在 `coordinator_root/provider-rate-limit-backoff.json`（`STATE_FILENAME`），連續命中次數沿用同一條指數曲線延長 deadline（5 分鐘起跳，封頂 16 倍～80 分鐘），確保跨 daemon restart 仍有效（不是行程內快取）。`manager.resume_workflow_run` 新增 `_provider_rate_limit_result`（`manager.py:6810-6836`）：ship_validator 拋出帶 `REASON_PROVIDER_RATE_LIMITED_CANONICAL` 的 `AuthorityValidationError` 時，記一筆 durable backoff 並回傳 `{"reason": "provider-rate-limited", "retry_after_epoch": ...}`，**不**再無條件覆寫 `needs_human`（真正的 authority 損毀仍走原本 needs_human＋re-raise）；函式最上方新增短路檢查（`resume_workflow_run` 起始處，`ship_validator is not None` 時），backoff 視窗內的任何 resume（不論 operator 或 periodic tick）直接回同一個 `provider-rate-limited` 結果，不再呼叫 `ship_validator`、不再重撞。未呼叫 `gh api rate_limit` 作可用性判準（該端點本身也吃配額）。
  - 已知取捨：短路檢查以 `ship_validator is not None` 作為「此 run 可能觸及 GitHub provider authority」的判準（canonical claim:v1 run 目前無論哪個 phase 都統一掛上同一個 ship_validator），因此限流視窗內會連帶暫停該 repo 所有 phase 的 resume（不只 review→ship 轉場），非僅限實際會撞 GitHub 的呼叫；視窗上限約 80 分鐘，取此較保守的行為換取單一、容易驗證的攔截點。
  - 4 個回歸測試檔（皆先確認 RED 再修復轉 GREEN）：`tests/test_github_rate_limit_signals.py`（共用分類器，含 "OAuth" 字樣的真實 secondary rate limit 訊息案例）、`tests/test_monitor_work_providers.py::test_github_provider_secondary_rate_limit_mentioning_oauth_is_not_misclassified_as_auth`、`tests/test_claim_provider_rate_limit_authority.py`（3 case：專屬 reason code、非限流 degraded 維持原 reason、仍是 `ValueError` 子類）、`tests/test_doctor.py`（`test_gh_auth_probe_reports_rate_limit_as_warn_not_authentication_failed` / `test_gh_auth_probe_still_reports_real_credential_failure_as_fail`）、`tests/test_provider_backoff.py`（9 case，含跨行程讀取模擬 restart 存活）、`tests/test_workflow_production_wiring.py`（`test_ship_validator_rate_limit_does_not_raise_or_require_operator` / `test_resume_before_backoff_deadline_short_circuits_without_calling_ship_validator`）。
