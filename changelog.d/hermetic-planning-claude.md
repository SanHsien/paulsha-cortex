### Fixed
- **Issue #404：planning claude 呼叫繼承 operator 全套 Claude Code 配置，且 plan 模式與回聲任務衝突**：`planning_runtime._planning_argv` 的 claude 分支過去帶 `--permission-mode plan`，且 `_invoke_json` 呼叫 `runner(...)` 時不帶 `env`，導致 claude CLI 直接繼承 operator `~/.claude`（superpowers plugin、記憶 hooks、user 層 CLAUDE.md、user MCP servers 全部注入），讓模型輸出摻雜與本次規劃無關的敘事；即使隔離掉這些注入項，plan 模式的系統提示（要求模型必須產出計畫或呼叫 `ExitPlanMode`）仍會與這裡「必須回傳純 JSON」的確定性回聲任務衝突，模型會以「須先給一份計畫」為由拒絕直接回 JSON（issue 404 實測矩陣已驗證）。修法：`_planning_argv` 的 claude 分支移除 `--permission-mode plan`（保留 `--tools ""`），安全層改由 no-tools＋`_invoke_json` 既有的一次性 disposable sandbox＋operator 樹前後 `_tree_snapshot` 比對（任何 operator 內容變化一律 fail-closed 並回滾）共同承擔；`_invoke_json` 新增 `_seed_hermetic_claude_env`，僅對 claude 身分在既有 `temp_dir` 下建一次性 `claude-config/`（0700），從 `Path.home()/".claude"/".credentials.json"` 播種（存在才播、chmod 0600），並以 `env={**os.environ, "CLAUDE_CONFIG_DIR": str(config_dir)}` 傳給 `runner(...)`，藉此同時隔離 operator 帳號下的 user MCP servers／plugins／hooks／使用者層 CLAUDE.md，但不影響登入態；查無登入憑證時不代為猜測，維持不設 `CLAUDE_CONFIG_DIR`，讓 CLI 自行回報 not logged in（`--bare` 與空 `CLAUDE_CONFIG_DIR` 皆已實測會弄丟登入態，不可用）；codex／agy 兩個 executor 維持不帶 env 覆寫，避免行為外溢。probes（`_probe_identity`）與 questioner／secondary planner／integrator 皆經同一個 `_invoke_json`，自動受益，未另外改動。新增 4 個回歸測試：claude argv 不含 `--permission-mode`／`plan`；`_invoke_json` 對 claude 身分注入的 `CLAUDE_CONFIG_DIR` 目錄與播種的 credentials 檔存在、內容正確、權限為 0700／0600；查無 credentials 時不設 `env`；codex 身分不受影響、不帶 env 覆寫。修正前 3 項新行為測試（含既有 argv 斷言更新後的既有測試）皆已確認 FAIL。
