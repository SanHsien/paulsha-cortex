### Fixed
- **Issue #385：README／Quickstart 預設安裝路徑追 mutable `main`，packaging CI 未覆蓋所有宣稱支援的 Python**：`README.md` 過去唯一的安裝指令是 `pipx install git+https://…paulsha-cortex.git`（無 tag，追 `main` 最新未發版碼），且完全沒有「這裝的是 main」告誡；`docs/onboarding/quickstart.md` 雖有告誡但第一推薦指令同樣先給 `main`。`.github/workflows/tests.yml` 的 install step 是 `pip install -e ".[test]" || pip install -e . || true`，但 `pyproject.toml` 未定義 `[project.optional-dependencies]`，`.[test]` 為不存在的 extra，加上尾端 `|| true` 使任一 Python 版本 editable install 失敗都不會讓 CI 紅（fail-open）；`build`／`smoke-install` 兩個 job 皆硬寫 Python 3.13，與 pytest job 的 3.10–3.13 matrix 不同調；`requires-python` 只有下界、無上界／classifiers，宣稱支援版本與 CI 實際覆蓋範圍對不齊；`release.yml` 未驗證 tag 與 `VERSION` 是否一致。修法：`README.md`／`docs/onboarding/quickstart.md` 安裝段改為預設推薦已發版、可回滾的 release（`pipx install "git+…@vX.Y.Z"` 或 GitHub Release wheel），`main` 安裝改列為明確標示「mutable / development / edge channel」的獨立段落；`pyproject.toml` 新增 `[project.optional-dependencies].test = ["pytest>=7"]`（tests 實際只需 stdlib `unittest.subTest` + `pytest` + 既有核心依賴 `PyYAML`，無其他第三方 import）與 `requires-python = ">=3.10,<3.14"` 加 4 個 Python 3.10–3.13 classifiers；`tests.yml` install step 移除 `|| true`，失敗即紅燈；`smoke-install` job 加上 Python 3.10–3.13 matrix（`build` job 維持單一 3.13——wheel 為 `py3-none-any` 純 Python universal wheel，已本機驗證），smoke 步驟另補 `python -c 'import paulsha_cortex'` 檢查；`release.yml` 的 `build` job 新增「Verify tag matches VERSION」步驟，比對 `GITHUB_REF` 的 `vX.Y.Z` 與 `VERSION` 檔內容，不一致即 `exit 1`（wheel version 由 `[tool.setuptools.dynamic]` 直讀 `VERSION`，tag↔VERSION 一致即隱含 wheel metadata 一致，不需另驗）。本機以獨立 venv 複驗：`pip install -e ".[test]"` 成功安裝 pytest 9.1.1 並跑滿全套 pytest（2084 passed/3 skipped，3 skip 為環境缺 `watchdog` 的既有行為，與本次改動無關）；`python -m build` 產出 `paulsha_cortex-0.1.4-py3-none-any.whl`，`twine check --strict` 通過，wheel METADATA 的 `Version`/`Classifier`/`Requires-Python` 皆符合新設定；乾淨 venv 安裝該 wheel 後 `import paulsha_cortex`、`cortex --version`（印出 `0.1.4`）、`cortex --help` 皆成功；tag↔VERSION 比對邏輯本機以 match／mismatch 兩案例模擬確認行為正確。
