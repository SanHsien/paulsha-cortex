### Fixed
- **Issue #380：deck compile 產出的 verification 骨架寫死 pytest**：`paulsha_cortex/deck/compile.py` 的 `_verification_skeleton` 過去對 `checks[name=policy]`、`tests`、`full_suite` 三處無條件硬寫 `["python3", "-m", "pytest", "-q"]`——`name` 宣告為 `"policy"` 但實際執行的是測試而非任何 policy 驗證，且對每個目標 repo 一律套用同一組 argv／timeout，未偵測目標 repo 實際宣告的驗證方式。修法：`_verification_skeleton` 改吃新增的 `compile_combo(..., repo_root=...)` 參數，透過既有 `paulsha_cortex.project_policy.resolve_project_policy()` 讀 `.project-policy.yml` 的 `preflight.steps`（typed：`kind: validation` / `kind: tests` + `argv` + `timeout_seconds`），`checks[name=policy]` 的 argv／timeout 取第一筆 `kind: validation` step，`tests`／`full_suite` 取第一筆 `kind: tests` step；`name` 維持 `"policy"` 不變，滿足 `coordinator/verification.py` 的 `validate_verification_contract` 對 auto_dispatch 要求「至少一筆 named policy command check」的前提。目標 repo 無 `.project-policy.yml`，或有檔但缺對應 kind 時，不留空（`validate_verification_contract` 要求 full_suite 為完整物件，留空會 `ContractValidationError` 使 spec 卡在 hold）——改填 fail-closed placeholder argv（`python3 -c "...sys.exit(...)"`，誤執行必非零退出）並在 compile 輸出印醒目 `[WARNING]`，翻 `dispatch: auto` 前必須手動補上真實指令。同步修正 `docs/superpowers/specs/fix-deck-emit-frontmatter-dispatch-contract.md` 建議樣板（原本示範 argv 同樣誤植 pytest）與 `paulsha_cortex/porcelain/init_sample.py` 的 `_required_fields`／`_next_steps`（自 #101 起 `target_branch`／`verification` 已非 `null`，提示文字過時未同步）。新增 3 個回歸測試（`tests/test_deck_compile.py`）：有 `preflight.steps` 的 repo 正確導出 argv／timeout 且契約合法；無 `.project-policy.yml` 與有檔缺 kind 兩種「偵測不到」情境皆填 fail-closed placeholder（實測 subprocess 執行 argv 確認非零退出）、印出 warning、契約仍合法，`name` 維持 `"policy"`。修正前三項新測試皆已確認 FAIL（`TypeError: compile_combo() got an unexpected keyword argument 'repo_root'`）。
