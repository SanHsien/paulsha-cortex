### Fixed
- **Issue #425：`test_stage9_project_monitor_service` 在 CI Python 3.13 job 偶發 `PermissionError`（測試隔離 flaky）**：CI 3.13 job 偶發 `PermissionError: [Errno 13] Permission denied: '.../ws2/projZ/docs/superpowers/workstreams/stage1-demo'`（`pathlib/_local.py:722` / `:515`），3.10–3.12 同 commit 穩定通過、3.13 重跑即過。逐行比對 CPython `pathlib/_local.py`／`_abc.py` 原始碼確認：`722` 是 `Path.mkdir()` 內的 `os.mkdir(self, mode)`、`515` 是 `Path.stat()` 內的 `os.stat(...)`——兩者都出自測試輔助函式 `_make_workspace()`（`tests/test_stage9_project_monitor_service.py`）未包 try/except 的 `ws.mkdir(parents=True, exist_ok=True)` 呼叫鏈，並非 issue 原始猜測的「測試自行 chmod 後未還原」（逐檔 grep 確認整個測試檔案完全沒有 chmod 呼叫）。真正成因：本測試檔每個 `Stage9ServerTests` 測試都會起至少一個 `MonitorServer` 背景 thread，`serve_forever()`（`paulsha_cortex/monitor/server.py`）在 `bind()` 前後暫時呼叫 `os.umask(0o177)` 再還原——`os.umask()` 是行程層級、非 thread-local 的全域狀態，若同一行程內另一 thread 在這極短窗口內執行 `Path.mkdir(parents=True)` 新建目錄，該目錄會意外繼承 `0600`（無 execute bit）；`is_dir()`/`exists()` 在 `_ignore_error()` 白名單裡從未含 `EACCES`（比對 3.10/3.12/3.13 原始碼三版邏輯相同，故非 3.13 語意變更，而是 3.13 pathlib 重寫後的內部呼叫時序讓這個既有 race window 更容易被排到），使 `mkdir(exist_ok=True)` 的救援路徑也一併炸開。`paulsha_cortex/monitor` 的掃描／serve 邏輯本身經複查全部透過 `checked_stat_mode`/`checked_resolve`（`fs.py`）與各處顯式 `except OSError` 防禦，對 3.13 無行為差異，故本次僅修測試基礎設施，未動 product code。新增 `_mkdir_resilient()`（bounded retry-on-`PermissionError`，預設 25 次、間隔 20ms，遠大於單次 `bind()` race window，對持續性權限問題仍照常 raise 不吞錯），並把檔案內全部 `X.mkdir(parents=True, exist_ok=True)` 呼叫（含 `_make_workspace` 本身與其餘 17 處同構呼叫）統一改用它，消除同一 race class 在檔案內其餘位置的殘留曝險。新增 `MkdirResilientTests`（3 個回歸測試）：模擬 ancestor 目錄暫時失去 execute bit 後背景 thread 還原、驗證 retry 能穿越 race window 成功建立目錄；驗證持續性權限問題仍會在耗盡 attempts 後正常 raise（非靜默吞錯）；`_make_workspace` 端到端重現 CI traceback 的確切呼叫鏈仍可在同樣的暫時性 race 下成功完成。因屬 CI-only、Python 3.13-only 的計時敏感 flake，本機 3.12 環境無法穩定重現原始 RED，故以上述直接單元驗證替代。全套 pytest 於本機 3.12：2314 passed、32 subtests passed（基線同數字，無回歸）。
